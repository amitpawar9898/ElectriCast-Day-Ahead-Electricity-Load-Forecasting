### 2.2 Timezone of raw timestamps, conversion, evidence

The raw `TS` values are Unix epoch seconds and are therefore UTC. The source generator's wall clock appears to be IST: **187,796 of 196,449** timestamps fall at `:30` UTC (which is `:00` IST), while **8,653** fall at `:00` UTC (which is `:30` IST); all 196,449 timestamps have second = 0. The `:00` UTC group is concentrated in three periods: 572 timestamps in June 2017, 7,460 in May 2018, and 621 in June 2018.

Interpreting the epoch as UTC and converting to IST is consistent with the data source, and moves the daily peak from **03:00** (unconverted UTC clock) to **09:00 IST**. However, the UI explicitly labels the processed dataset as UTC, which is wrong.

**Verbatim cleaning — `backend/train_models.py:81–91`:**

```python
    # Resample hourly & filter 2017
    hourly = full.resample("h").sum()
    df = hourly.loc["2017-01-01":"2017-12-31"].copy()

    # Outlier cap at mean + 3σ
    upper = df["W"].mean() + 3 * df["W"].std()
    df["W"] = df["W"].clip(upper=upper)

    # Gap fill — zero = sensor dropout
    df["W"] = df["W"].replace(0, np.nan).interpolate("linear")
    df["W"] = df["W"].fillna(df["W"].median())
```

Consequences:

- `resample("h").sum()` produces exactly `0.0` for every hour with no raw row. Those zeros are then indistinguishable from genuine zero consumption and are all replaced with `NaN`.
- 11 rows above `mean + 3σ` (= **22,128.217 Wh**) are clipped.
- Linear interpolation fills gaps in both directions between known points; the final `fillna(median)` handles edges.
- The cap threshold and median are computed on the **full 2017 dataset**, including the test half, so test data influences train preprocessing.
- There is no count of attempted vs successfully read CSVs; any parse error is swallowed by `except Exception: pass`.

**Zero / near-zero counts and longest runs (2017 hourly, IST):**

| After cleaning | **0** | 2 | **1,475** | 0 h | **191 h** (2017-03-29 19:00 → 2017-04-06 17:00) |

### 2.5 Uploaded dataset handling

`/api/upload-validate` accepts a CSV with `Unix Timestamp` and `Energy Consumption (kWh)`, converts UTC → IST, resamples by **mean** (training used **sum**), interpolates linearly, then keeps only the **first six months**. The uploaded sample's first six months are 2020-01-01 → 2020-06-30: **4,363 hourly rows**, of which **4,195** survive feature construction (168 h lost to lag `dropna`). Upload mean is 54.8 (labeled kWh), training mean is 7,400.2 (actually Wh), so a scale factor of **135.118** is applied before inference and reversed afterward.

Observed response for the bundled file: HTTP 200 in ~3.7 s; XGBoost R² **−0.6799**, RMSE **30.2**, MAE **24.7**, sMAPE **48.82%**. The monthly means are nearly flat (54.1–55.6), consistent with the dataset's random generator rather than a forecastable load pattern. Because the validation data is random and distribution-shifted, these metrics say nothing about model quality.

### 3.1 Feature engineering

The active feature engineering is the XGBoost builder. The earlier `load_india_2017` also adds calendar features to the frame, but `build_xgb_features` recomputes them from the index.

**Verbatim calendar features — `backend/train_models.py:93–101`:**

```python

    df["day_of_week"] = df.index.dayofweek
    df["month"] = df.index.month
    df["is_weekend"] = (df["day_of_week"] >= 5).astype(int)

```

**Verbatim full feature builder — `backend/train_models.py:325–345`:**

```python
def build_xgb_features(df, target_col="W"):
    """Build XGBoost features from an hourly DataFrame with a power column."""
    d = df[[target_col]].copy()
    d.columns = ["W"]

    for lag in [1, 2, 3, 6, 12, 24, 48, 168]:
        d[f"lag_{lag}"] = d["W"].shift(lag)
    for w in [6, 12, 24]:
        d[f"roll_mean_{w}"] = d["W"].shift(1).rolling(w).mean()
        d[f"roll_std_{w}"] = d["W"].shift(1).rolling(w).std()

    d["hour"] = df.index.hour
    d["dayofweek"] = df.index.dayofweek
    d["month"] = df.index.month
    d["hour_sin"] = np.sin(2 * np.pi * df.index.hour / 24)
    d["hour_cos"] = np.cos(2 * np.pi * df.index.hour / 24)
    d["month_sin"] = np.sin(2 * np.pi * df.index.month / 12)
    d["month_cos"] = np.cos(2 * np.pi * df.index.month / 12)
    d["is_weekend"] = (df.index.dayofweek >= 5).astype(int)

    return d.dropna()
```

The resulting model matrix has **22 features**:

`lag_1, lag_2, lag_3, lag_6, lag_12, lag_24, lag_48, lag_168, roll_mean_6, roll_std_6, roll_mean_12, roll_std_12, roll_mean_24, roll_std_24, hour, dayofweek, month, hour_sin, hour_cos, month_sin, month_cos, is_weekend`

`dropna()` removes the first 168 rows of the year (because `lag_168` and the 6/12/24 rolling windows are undefined). This leaves **8,592** usable feature rows: 4,176 train (2017-01-08 → 2017-06-30) and 4,416 test. The saved `xgb_feature_cols.json` and the artifact's `feature_names` both contain these 22 names in this order.

### 3.2 Shift and leakage audit

- Every lag uses `shift(lag)` with lag ≥ 1: `[1, 2, 3, 6, 12, 24, 48, 168]`.
- Every rolling statistic uses `d["W"].shift(1).rolling(w).mean()` / `.std()`. The explicit `shift(1)` prevents the current target from entering its own rolling window.
- No feature contains `W(t)`. Time features are derived only from the timestamp.
- **However, the test features are built from actual test-period `W` values.** `build_xgb_features` is called on the entire 2017 frame before splitting, and `test_mask` only selects rows; the lags for July–December are the observed July–December loads, not model outputs. The XGBoost evaluation is therefore **teacher-forced one-step-ahead**, not a six-month forecast. This is the single largest methodological issue behind the reported 0.8238 R².
- The outlier cap and median fill are also computed on the full year before splitting, a smaller but real preprocessing leak.
- No feature uses future values: all lags are backward-looking; interpolation during cleaning can use the next known value in both train and test.

```python
def smape(y_true, y_pred):
    a, p = np.array(y_true, dtype=float), np.array(y_pred, dtype=float)
    denom = np.abs(a) + np.abs(p)
    mask = denom > 0
    return round(float(np.mean(2 * np.abs(a[mask] - p[mask]) / denom[mask]) * 100), 2)


def calc_metrics(y_true, y_pred):
    return {

        "RMSE": round(float(np.sqrt(mean_squared_error(y_true, y_pred))), 1),
        "MAE": round(float(mean_absolute_error(y_true, y_pred)), 1),

        pd.to_datetime(full["TS"], unit="s")
        .dt.tz_localize("UTC")
        .dt.tz_convert("Asia/Kolkata")
    )
    full = full.drop(columns="TS").set_index("datetime").sort_index()

    # Resample hourly & filter 2017
    hourly = full.resample("h").sum()
    df = hourly.loc["2017-01-01":"2017-12-31"].copy()

    # Outlier cap at mean + 3σ
    upper = df["W"].mean() + 3 * df["W"].std()
    df["W"] = df["W"].clip(upper=upper)

    # Gap fill — zero = sensor dropout
    df["W"] = df["W"].replace(0, np.nan).interpolate("linear")
    df["W"] = df["W"].fillna(df["W"].median())

    # Feature engineering
    df["hour"] = df.index.hour
    df["day_of_week"] = df.index.dayofweek
    df["month"] = df.index.month
    df["is_weekend"] = (df["day_of_week"] >= 5).astype(int)
    df["hour_sin"] = np.sin(2 * np.pi * df["hour"] / 24)
    df["hour_cos"] = np.cos(2 * np.pi * df["hour"] / 24)
    df["month_sin"] = np.sin(2 * np.pi * df["month"] / 12)
    df["month_cos"] = np.cos(2 * np.pi * df["month"] / 12)

    print(f"    2017 shape: {df.shape} | W: {df['W'].min():.0f}–{df['W'].max():.0f} Wh")
    return df

# ── SARIMA ────────────────────────────────────────────────────────

def train_sarima(train_vals, n_forecast):
    print("[4/5] Training SARIMA …")
    from statsmodels.tsa.statespace.sarimax import SARIMAX

    n = min(len(train_vals), SARIMA_MAX_TRAIN)
    subset = train_vals[-n:]
    print(f"    Fitting on last {n} hours …")

    model = SARIMAX(
        subset,
        order=(1, 1, 1),
        seasonal_order=(1, 1, 1, 24),
        enforce_stationarity=False,
        enforce_invertibility=False,
    )
    result = model.fit(disp=False, maxiter=300)
    print(f"    AIC = {result.aic:.0f}")

    preds = result.forecast(steps=n_forecast)
    preds = np.maximum(np.array(preds, dtype=float), 0)
    print(f"    {len(preds)} predictions")
    return preds

def build_xgb_features(df, target_col="W"):
    """Build XGBoost features from an hourly DataFrame with a power column."""
    d = df[[target_col]].copy()
    d.columns = ["W"]

    for lag in [1, 2, 3, 6, 12, 24, 48, 168]:
        d[f"lag_{lag}"] = d["W"].shift(lag)
    for w in [6, 12, 24]:
        d[f"roll_mean_{w}"] = d["W"].shift(1).rolling(w).mean()
        d[f"roll_std_{w}"] = d["W"].shift(1).rolling(w).std()

    d["hour"] = df.index.hour
    d["dayofweek"] = df.index.dayofweek
    d["month"] = df.index.month
    d["hour_sin"] = np.sin(2 * np.pi * df.index.hour / 24)
    d["hour_cos"] = np.cos(2 * np.pi * df.index.hour / 24)
    d["month_sin"] = np.sin(2 * np.pi * df.index.month / 12)
    d["month_cos"] = np.cos(2 * np.pi * df.index.month / 12)
    d["is_weekend"] = (df.index.dayofweek >= 5).astype(int)

    return d.dropna()


def train_xgboost(df_2017, split_time):
    global XGB_FEATURE_COLS
    print("[3/5] Training XGBoost …")

    df_feat = build_xgb_features(df_2017, target_col="W")

    feat_cols = [c for c in df_feat.columns if c != "W"]
    XGB_FEATURE_COLS = feat_cols
    X = df_feat[feat_cols]

        "lstm": to_list(mg["lstm"]),
        "sarima": to_list(mg["sarima"]),
        "xgboost": to_list(mg["xgboost"]),

    monthly_errors = {"months": test_months, "lstm": {}, "sarima": {}, "xgboost": {}}
    for m_num in mg.index:

        m_name = MONTH_NAMES[m_num - 1]

        for model_key, m_pred in [("lstm", lstm_preds[mask]),

        dow_df = daily_df.loc[mask]

        weekly_pattern[dow_name] = hw

    return {
        "hourly_labels": hourly_labels,
        "actual": to_list(test_vals),
        "lstm": to_list(lstm_preds),
        "sarima": to_list(sarima_preds),

        "monthly": monthly_pred,
        "daily": daily_pred,
        "weekly_pattern": weekly_pattern,
        "monthly_errors": monthly_errors,
    }
```

### 4.2 SARIMA

- Order: **SARIMA(1,1,1)(1,1,1,24)** — one non-seasonal AR/MA term, one difference, one seasonal AR/MA term at lag 24.
- Training window: `n = min(len(train_vals), SARIMA_MAX_TRAIN)` with `SARIMA_MAX_TRAIN = 1000`; it fits on the **last 1,000 training hours** (approximately 2017-05-20 → 2017-06-30), not the full 4,344-hour train set.
- Prediction method: a **single 4,416-step out-of-sample forecast** with no rolling refit and no use of test actuals.
- Forecasts are clipped at zero. With the model trained on only ~6 weeks of data, the forecast decays toward zero: monthly predicted means are 6,188.1 (Jul), 1,646.58 (Aug), 57.41 (Sep), 0.00 (Oct–Dec), producing R² **−1.3261**, RMSE **7,153.7**, MAE **5,578.2**, sMAPE **165.23%**.

```python
def smape(y_true, y_pred):
    a, p = np.array(y_true, dtype=float), np.array(y_pred, dtype=float)
    denom = np.abs(a) + np.abs(p)
    mask = denom > 0
    return round(float(np.mean(2 * np.abs(a[mask] - p[mask]) / denom[mask]) * 100), 2)


def calc_metrics(y_true, y_pred):
    return {
        "R2": round(float(r2_score(y_true, y_pred)), 4),
        "RMSE": round(float(np.sqrt(mean_squared_error(y_true, y_pred))), 1),
        "MAE": round(float(mean_absolute_error(y_true, y_pred)), 1),
        "sMAPE": smape(y_true, y_pred),
    }
```

Note: sMAPE is computed over every row where `|actual| + |predicted| > 0`. There is **no `W > 100` exclusion**, contrary to the README. A row with `actual=0` and `predicted>0` contributes 200%. R², RMSE, and MAE are computed on all 4,416 test hours.

### 5.4 Where the LSTM zeros originate

- `lstm_preds = np.zeros(len(test_vals))` at `train_models.py:509`.
- Those zeros flow into `hourly`, `daily`, `monthly`, and `weekly_pattern` arrays via `build_predictions`.
- The `metrics.lstm` object is not computed from the zeros; it is hardcoded to `{R2:0, RMSE:0, MAE:0, sMAPE:0}` at lines 520–526.

```python
def _load_lstm_model():
    """Load saved LSTM model and scaler."""
    import torch
    import torch.nn as nn

    class LSTMModel(nn.Module):
        def __init__(self):
            super().__init__()
            self.lstm1 = nn.LSTM(1, 64, batch_first=True)
            self.drop1 = nn.Dropout(0.2)
            self.lstm2 = nn.LSTM(64, 32, batch_first=True)
            self.drop2 = nn.Dropout(0.2)
            self.fc = nn.Linear(32, 1)

            x, _ = self.lstm1(x)
            x = self.drop1(x)
            x, _ = self.lstm2(x)
            x = self.drop2(x[:, -1, :])
            return self.fc(x)

        d[f"roll_std_{w}"] = d["W"].shift(1).rolling(w).std()

def _process_smart_home_csv(raw_bytes: bytes):
    """Parse smart_home_dataset CSV, convert to IST hourly, return first 6 months."""
    df = pd.read_csv(io.BytesIO(raw_bytes))

    required = {"Unix Timestamp", "Energy Consumption (kWh)"}
    if not required.issubset(set(df.columns)):
        raise ValueError(
            f"CSV must contain columns: {required}. Found: {list(df.columns)}"
        )

    df["datetime"] = pd.to_datetime(df["Unix Timestamp"], unit="s", utc=True)
    # Convert UTC → IST to match training data timezone
    df["datetime"] = df["datetime"].dt.tz_convert("Asia/Kolkata")
    df = df.set_index("datetime").sort_index()

    # Resample to hourly (mean consumption per hour)
    hourly = df[["Energy Consumption (kWh)"]].resample("h").mean()
    hourly = hourly.interpolate("linear").dropna()
    hourly.columns = ["W"]

    # Take first 6 months
    start_year = hourly.index[0].year
    start_month = hourly.index[0].month
    # Calculate 6 months forward
    end_month = start_month + 5
    end_year = start_year
    if end_month > 12:
        end_month -= 12
        end_year += 1
    cutoff = f"{end_year}-{end_month:02d}-{pd.Timestamp(end_year, end_month, 1).days_in_month}"
    first_6m = hourly.loc[:cutoff].copy()

    return first_6m, hourly
```

### 6.3 Backend observations

- The endpoint reads the entire upload into memory before checking the 50 MB limit (`raw = await file.read()` then `len(raw)`), so a large upload can consume memory before rejection.
- Filename validation is case-sensitive (`.csv` only).
- Upload validation is **not** a forecasting evaluation: features are built from actual uploaded `W` lags, so predictions are teacher-forced one-step-ahead. Metrics are computed on the first six months with no held-out split.
- The scale factor `train_mean / upload_mean` can be enormous when the upload mean is tiny; here it is **135.118**. It changes the model input distribution and is reversed only for reporting.
- The upload resamples with `.mean()`, while training uses `.sum()`; this is a semantic mismatch between datasets.
- The upload sample is random synthetic data (per its README), so the reported R² −0.6799 is not evidence about the model's real-world performance.
- CORS is `allow_origins=["*"]` with all methods/headers; there is no authentication or rate limiting.
- `_load_lstm_model()` is dead code and would fail if ever called because no `lstm_model.pt`/`lstm_scaler.pkl` exists.

### 8.3 Data interpretation caveats

- The 39 CSVs are separate apartments; `W1+W2+W3` per timestamp is summed across all reporting apartments. The target is a building/campus aggregate, not one household.
- Active apartment count changes from 23–26 to 39 in November; the aggregate level shift is largely a reporting-coverage change, not necessarily demand.
- `W` is documented and labeled as Wh; all UI strings say kWh.
- The upload sample is simulated and random by its own README.

## 10-LINE RISK SUMMARY

1. A disabled LSTM is shipped as a real model; its hardcoded zero metrics win RMSE, MAE, and sMAPE BEST badges and appear throughout the UI.
2. XGBoost's 0.8238 R² is teacher-forced one-step-ahead using actual test-period lags, not a genuine six-month forecast.
3. SARIMA is fit on only the last 1,000 training hours and emits one 4,416-step forecast that decays to zero (R² −1.3261).
4. The yearly “full hourly” chart displays only 8 points, hiding seasonal structure and making the trend unreadable.
5. The UI claims an 80/20 split, but the actual split is 4,344/4,416 hours (49.59%/50.41%), hardcoded in the page.
6. Every displayed value and error is labeled kWh although the data and metrics are Wh, understating magnitudes by 1,000×.
7. 1,691 empty hours are converted to zero and interpolated, including a fabricated 272-hour gap, while December suffers a severe reporting collapse.
8. Upload validation applies a 135× scale factor to random synthetic data, reports R² −0.6799, and colors the failing metric green.
9. The container image lacks `models/`, so upload validation returns 503, while its `curl` healthcheck is likely unavailable and `VITE_API_URL` is ignored at runtime.
10. No tests, CI, or `.gitignore` exist; `node_modules` (2,389 files) and `.DS_Store` are tracked, and README/Copilot docs contradict the actual implementation.
